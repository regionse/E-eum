# 잇다 변경 기록 — 인수인계용

**규칙: 코드를 고치거나·바꾸거나·지우거나·만들 때마다 여기에 적는다.**
「무엇을 · 어느 파일에서 · 왜 · 어떻게 확인했나」 네 가지를 반드시 남긴다.

- 최신이 **위**로 온다.
- 「왜」가 없으면 다음 사람이 되돌린다. **왜를 꼭 적을 것.**
- 실패한 시도도 적는다. 「해봤는데 안 됐다」가 다음 사람의 시간을 아낀다.

> 측정·근거는 **실측기록_잇다.md 6~9장**에 전부 있다. 여기는 «무엇을 왜 고쳤나»만 적는다.

### 출발점 — 실측으로 잡은 것

같은 「할머니를 돌보다」에 어미만 바꾼 6종이 **전부 동일하게** `활동유형=돕기·돌봄` 으로 기록됐다.
「돌봐야 해요」(의무)와 「돌보고 싶어요」(희망)가 **구조적으로 구분 불가**였다.
그리고 「할머니 돌보느라 아무것도 못 해봤어요」가 **출처 user** 로 선호에 들어갔다(재현 3/3).
`verify_slots` 는 통과시킨다 — 근거로 「할머니 돌보느라」를 대면 그 글자가 발화에 있어서다.
**근거는 있는데 뜻이 뒤집혀 있었다.** 우리 사용자군에게 가장 흔한 문장 형태다.

### 6. ★ 검색 질의 순서 — 「닻」이 잘려나가고 있었다

**증상** — 「제과제빵 배웠어요」 → 「만드는 게 재밌었어요」 에
**목공예·가구제작·금속공예·도자공예·섬유공예** 가 나왔다. 제과제빵이 **하나도** 없다.

**단계별로 재보니 검색은 멀쩡했다:**
```
「제과제빵 만들기 사람」        → 제과 · 제빵 · 한과제조 · 떡제조   ✅
「무언가를 직접 만드는 활동」     → 목공예 · 가구제작 · 도자공예
```
질의 하나씩은 정확하다. **합칠 때 뒤집힌다.**

**원인** — `match_jobs` 는 `queries[:4]` 로 **앞 4개만** 쓴다. 그 주석이 이렇게 적어 뒀다:
> **앞자리가 우선**이므로 호출부는 결정론적 앵커(사용자 원문·**슬롯 질의**)를 **앞에** 두고
> LLM 변형을 뒤에 둔다 — 잘려도 앵커는 남는다.

**그런데 구현이 정반대였다.**
```python
qs = [q] + [alts…]            # LLM 변형이 앞
for _sq in self._slot_queries(profile):
    qs.append(_sq.strip())    # 코드가 조립한 «닻»이 뒤 → [:4] 에서 잘림
```

그래서 실제로 쓰인 앞 4개에 「제과제빵」이 하나도 없었다.
그리고 RRF 는 「여러 순위에 공통으로 오른 후보」를 올리므로, 사실상 같은 뜻인
LLM 변형 6개가 **중복 투표**가 되어 사용자가 실제로 말한 낱말을 눌러 버렸다.

**고침** — 순서를 뒤집었다: `q` → **슬롯 질의(닻)** → LLM 변형.

| | 앞 4개 | 결과 |
|---|---|---|
전 | 만드는 게 재밌었어요 · 무언가를 직접 만드는 활동 · 손으로 제작하는 작업 · 창작물을 만드는 일 | 목공예·가구제작·금속공예… **제과제빵 0개** |
후 | 만드는 게 재밌었어요 · **제과제빵 만들기 돕기·돌봄 사람** · … | **한과제조·제과·제빵·떡제조** |

**확인** — 골든셋 **34/34 · 76초**(전 82초). 검색을 건드렸는데 회귀 없음.

⚠ **남은 문제** — 후보 상위가 제과제빵으로 바뀌었는데도 최종 카드는 「음식조리공통직무」였다.
   `llm_pick` 에 넘어가는 후보 목록(클러스터 대표)에 **제빵이 안 들어간다.** 별개 자리다. **미해결.**

### 7. ★ 「종류」를 **값 단위**로 — 그리고 검색·순위에 실제로 반영

6장에서 「종류」를 뽑게 만들었지만 **아무 데서도 안 쓰고 있었다.** 저장만 하고 끝이었다.
6장을 만든 그 대화에서 바로 증거가 나왔다:

```
슬롯   활동유형 = [만들기(원함), 돕기·돌봄(못함)]   다루는대상 = [사람(코드가 채움)]
검색어 「음식 만들기 돕기·돌봄 사람」  →  아이돌봄 · 요양지원 · 가사지원 …
                    ↑ 「못 했다」고 한 것이 검색을 끌고 갔다
```

**둘을 고쳤다.**

**① `_slot_kind` 를 축 단위 → 값 단위로** `{슬롯: 종류}` → `{슬롯: {값: 종류}}`
   축 하나에 값이 여럿이면 축 대표만으로는 「만들기는 살리고 돌봄만 뺀다」가 불가능하다.
   축 대표가 필요한 자리(`can_land` 의 가중)는 `axis_kind()` 가 «무게가 큰 값»을 돌려준다 — 동작 동일.

**② `wanted_vals(p, 축)` 신설** — 「못함」이 아닌 값만 돌려준다. 쓰는 곳 **셋**:
   · `_search_query()`   — 닻 문장
   · `_slot_queries()`   — 슬롯 조합 질의
   · `ATTR_LIFT` 가중    — `job_attr` 태그 일치 보너스
   ⚠ **셋 다 고쳐야 한다.** 검색만 고치면 순위가 여전히 돌봄을 끌어올린다(실측으로 확인했다).

| | 상위 6 | 제빵 | 돌봄 직업 |
|---|---|---|---|
전 | 음식조리공통직무·제빵·**아이돌봄**·제과… | 2위 | 1개 |
후 | **제빵·제과**·한과제조·음식조리공통직무… | **1위** | **0개** |

⚠ **경험이 사라지는 건 아니다.** 「돌봄을 했다」는 사실은 대화 이력에 그대로 남고
  최종선택(`llm_pick`)이 그 이력을 읽는다. 여기서 빼는 것은 **검색 방향**뿐이다.

**확인** — 0원 검사 7종 유지 · 골든셋 **34/34 · 76초** · 태그 가중 로그에서 「돕기·돌봄」 사라짐 ·
  같은 대화 **3회 반복 결과 완전 동일**(흔들림 0).

### 8. ★★ 칩을 «말로» 고르는 답 — 계단식으로 받는다

칩 `[가구제작·목공예·한과제조·떡제조·금속공예]` 를 띄워 놓고 실측한 것:

| 사용자 말 | 전 | 후 |
|---|---|---|
「떡제조」·「세 번째요」 | ✅ | ✅ |
「빵이요」·「떡이요」 | ❌ None | ✅ |
「공예요」·「공예 쪽이요」 | ❌ None | ✅ 3개 |
「제과제빵쪽이요」·「식품쪽이요」 | ❌ None | ✅ 2개 |
**「음식 쪽이요」·「먹는 거요」** | ❌ None | ✅ 2개(LLM) |

**못 알아보면 그 말이 «새 관심분야»로 떨어져 검색어를 오염시킨다.**
실제로 「음식 쪽이요」 → `관심분야 += 음식` → 카드가 **음식조리공통직무**(한식·중식·일식조리기능사)가 됐다.
제과제빵을 배운 사람에게 조리사를 권한 것이다.

**계단으로 만들었다 — 싼 것부터. 앞에서 걸리면 뒤는 «안 돈다».**

| 단 | 무엇 | 잡는 것 | 비용 |
|---|---|---|---|
① | 이름 그대로 · 번호 (기존) | 「떡제조」·「2번이요」 | 0원 |
② | **조사를 벗기고 양방향** | 「빵이요」→「빵」→제빵 | 0원 |
③ | **NCS 분류명으로도** | 「공예 쪽이요」→공예 3개 | 0원 · DB 1회 |
④ | **LLM 한 번** | 「음식 쪽이요」 | **0.17원** (드묾) |

**②가 «낱말 더하기»가 아닌 이유** — 한국어 **조사는 닫힌 집합**이다(주격 이/가 · 목적격 을/를 ·
보조사 은/는/도/만 · 부사격 로/으로/랑/과 · 종결 요/예요/입니다). 유한하고 문법적이라 열거가 완결된다.
반면 **동의어(음식↔식품)는 열린 집합**이라 목록으로 못 닫는다 → 그건 ④가 받는다.

⚠ **한 갈래만 벗기면 안 된다.** 「공예요」는 '요'를 벗기면 「공예」지만 **'예요'를 벗기면 「공」**이다.
  먼저 걸리는 것 하나만 벗기던 첫 판은 「공」이 나와 통째로 놓쳤다.
  ⇒ `_pick_stems()` 가 **모든 갈래**를 내놓고 호출부가 긴 것부터 시험한다.

⚠ **분류명의 가운뎃점을 지운다.** 중분류가 「제과·제빵·떡제조」인데 사용자가 말한 「제과제빵」이
  '·' 하나 때문에 안 걸렸다. `_FILLER_RE` 로 정규화.

**④(LLM)를 «마지막»에 둔 이유** — 칩 이름·번호·조사·분류명에서 걸리면 호출 자체가 없다.
  평소 비용은 **0원 그대로**다. 시스템 프롬프트도 안 붙인다(게이트와 같은 방식).

**실측 6/6** — 「음식 쪽이요」·「먹는 거요」→한과제조·떡제조 · 「나무 쪽이요」→가구제작·목공예
  (**금속공예를 뺐다**) · 「손으로 만지는 거요」→없음(모호하면 안 고른다) ·
  「아 그냥 요양보호사 할래요」·「할머니가 또 편찮으세요」→**없음**(화제 전환을 정확히 가른다)

**⇒ 「칩 선택 실패 시 슬롯 오염 차단」은 «넣지 않았다».** ④가 화제 전환에 None 을 주므로,
  그때 새 슬롯으로 담기는 것이 **맞는 동작**이다. 차단을 넣으면 오히려 화제 전환을 막는다.

**대화 실측** — 「제과제빵 배웠어요…」→「만드는 게 재밌었어요」→「음식 쪽이요」
  · 전: 카드 **음식조리공통직무** · 관심분야 [제과제빵, **음식**]
  · 후: 카드 **한과제조** · 관심분야 [제과제빵] — 오염 없음

**확인** — 골든셋 **34/34 · 77초** · 회귀 검사(cats 없이) 6종 기존과 동일.

⚠ **남은 것** — 칩에 **제과·제빵이 아예 안 올라온다**(한과제조·떡제조만).

```
🔴 그냥 다 놓아버리고 싶어요 · 내일이 안 왔으면 좋겠어요

```
응답이 차갑진 않았다(공감은 했다). **109 를 안 줬을 뿐이다.**

⚠ **6120 주석의 서술을 정정한다.** 거기엔 「낱말표를 빠져나간 위기 진술은 Gemini 안전필터가

⚠ 「다들 저 없는 게 나을 거예요」·「짐만 되는 것 같아서요」는 위험 평가에서 **핵심 지표**로

    문헌이 권하는 바로 그 방향이다.** 이미 앞서 있었다.

**고침 — `_harm_gate` 에 「위기」 필드를 «같은 호출»에 추가.** 비용 0원 · 지연 0초.

```
위기: [아니오·본인·제3자]      ← 신설
```

### 14. ★ 「이미 들은 것을 처음 듣는 것처럼 되묻던」 것의 «진짜» 자리 — `ask_reply` 꼬리

11장에서 `profile_text` 에 종류를 넣어 ⑥ 문지아를 고쳤는데 **③ 박민재에서 같은 증상이 남았다.**
긴 발화(120·92·80·46자)로 돌려 보니 원인이 다른 데 있었다.

```
3턴 action=SEARCH → 💬「사무직 쪽을 말씀해 주셨네요. 혹시 그 일을 «해보신 적이 있으세요»?」
4턴 action=SEARCH → 💬「사무직 쪽을 말씀해 주셨네요. 혹시 그 일을 «해보신 적이 있으세요»?」
                     ↑ 글자까지 동일 = «모델의 말이 아니라 코드가 쓴 말»이다
```
`ask_reply()` 의 마지막 fallback(세 축이 다 차서 물어볼 빈 슬롯이 없을 때) 이었다.
**두 가지가 틀려 있었다.**

**① `_iv[0]` — «맨 처음» 값을 쓴다.**
  박민재 4턴에 「사무직」(1턴 값), 문지아 3턴에 「요양보호사」(1턴 값)를 꺼낸다.
  그 사이에 사용자가 말한 것(엑셀·문서정리·대인부담·시간부족)을 통째로 무시한다.
  ⇒ **마지막에 들은 것**을 쓴다. 「원함」으로 말한 것이 있으면 그것을 먼저.

**② 「해보신 적이 있으세요?」를 «이미 해봤다고 들은 것»에 묻는다.**
```
🧑 「사무직으로 일한 지 3년쯤 됐는데요」  → 관심분야{사무직: «해봤음»}
🤖 「사무직 쪽을 … 혹시 그 일을 «해보신 적이 있으세요»?」
```
  **우리가 답을 아는 질문이다.** 사용자에게는 「안 듣고 있다」로 읽힌다.
  ⇒ 이제 `_slot_kind` 가 있으니 종류별로 갈라 묻는다:
```
해봤음 → 「… 해보셨군요. 그 일에서 그나마 할 만했던 게 어떤 부분이었어요?」
못함   → 「그럼 방향을 좀 바꿔볼까요 — 해보고 싶었는데 못 해본 일이 있으세요?」
그 외  → (기존) 「… 혹시 그 일을 해보신 적이 있으세요?」
```

**확인 — 둘 다 살아났다.**
```
③ 박민재  3턴 [해보신 적…] → **[card · 빅데이터운영·관리]**
          4턴 카드 유지 + 「주말에만 시간 내실 수 있는 상황을 고려해서…」 ← 제약을 읽는다
          중복 0
⑥ 문지아  3턴 「혼자 조용히 집중해서 하는 일을 좋아하시는군요. 사람을 대하는 일보다는
               컴퓨터나 기계, 혹은 물건을 다루는 쪽이…」   중복 0
골든셋 34/34 · 83초
```

⚠ **긴 발화로 돌려야 보인다.** 짧은 발화(3~10자)만 던지면 이 자리에 도달하지 않는다.
  실제 사용자는 협조적일수록 길게 쓴다(대조군 ③ 이 그 유형이다).
  **분해 자체는 문제가 없었다** — 120자에서 근거까지 정확히 떼어냈고, 92자에서 4슬롯을
  한 번에 뽑았다. 망가진 것은 «듣기»가 아니라 «말하기»였다.

### 15. 「그만둔 일」로 검색하던 것 — 「못함」의 정의를 넓혔다

페르소나 ① 정지훈이 잡았다.
```
🧑 편의점 야간이랑 물류센터 상하차 해봤어요
🧑 둘 다 «몸이 힘들어서 그만뒀어요»
   검색 닻 = 「편의점 야간 물류센터 상하차 관리·운영 운전·조작 기계·설비」
```
**그만둔 일로 검색해서 비슷한 육체노동을 다시 권하게 된다.**

⚠ `_NOT_INTEREST`(17개)는 「알바·정규직·월급」 같은 **고용형태**만 거른다.
  「편의점 야간」은 구체적 직무명이라 안 걸린다.
  **여기에 낱말을 더하는 것은 답이 아니다**(이 파일이 오늘 내내 확인한 그 실수다).

**진짜 원인 — 「해봤고 그만둔 일」을 담을 종류가 없었다.**
`못함` 의 정의가 「그것에 묶여 있거나 그것 때문에 다른 걸 못 했다」였는데,
**「그것을 계속할 수 없었다」가 빠져 있었다.**

**고침** — 정의를 넓혔다(프롬프트 + `KIND_DESC` 둘 다).
```
못함 = 그것에 묶여 있다 · 그것 때문에 다른 걸 못 했다
      + **해봤지만 계속할 수 없어 그만뒀다**  ← 신설
가르는 기준 = 「그만두거나 못 하겠다」는 말이 붙었나
  "편의점에서 일했어요"              → 해봤음 (사실만 말했다)
  "편의점 했는데 힘들어서 그만뒀어요"  → 못함  (계속 못 했다고 말했다)
```

**확인**
```
정지훈  종류 {편의점 야간: 못함, 물류센터 상하차: 못함}
        검색닻 '편의점 야간 물류센터 상하차 관리·운영 운전·조작 기계·설비'
             → **'분석·연구 컴퓨터·데이터'**   (그만둔 일이 빠졌다)
대조    「편의점에서 일했어요」 → 해봤음 유지    (경계가 선다)
골든셋  34/34 · 82초
```

⚠ **⑪ 조현우의 「카드가 없는데 카드 얘기」는 재현되지 않았다.** 그 사이 들어간
  11~14장 수정으로 사라진 것으로 보인다. 지금은 카드가 실제로 있을 때만 그 말을 한다.
  ⚠ 다만 **자격 요건을 «말하기 시작»하는 경향**은 남아 있다
  (「사회복지사 2급의 경우 학점 이수와 실습 등…」). 그 내용이 맞는지 우리는 검증하지 못한다.
  페르소나 파일이 «최악»으로 표시한 ③(같이 틀린 소리)에 가까워질 수 있는 자리다. **미해결.**

### 17. ★ 슬롯이 «쌓이기만» 하던 것 — 무효화(invalidation)의 최소판

동적 페르소나 80턴에서 관측:
```
관심분야 ["편의점", "물류센터", "편의점 알바"]        ← 같은 것을 세 이름으로
종류     {편의점: 해봤음, 편의점 알바: 못함, 편의점 야간: 못함}   ← 셋이 따로 산다
검색어   「편의점 물류센터 편의점 알바 …」            ← 같은 신호를 세 번 센다
```
`merge()` 의 `dict.fromkeys(cur + add)` 는 **글자가 똑같을 때만** 지운다.

**문헌 — 이 문제의 이름은 «무효화»다**
- **Graphiti**(운영 시스템) — "maintains **fact validity windows (non-lossy history)**"
  사실에 유효 기간을 두고 오래된 것은 **지우는 대신 무효화**한다.
- 하이브리드가 표준이다 — "dynamic **session summarization** and weighted **KG-based user
  modeling**". 잇다도 이미 그 구조다(`_summary` 서사 + `_facts` 사실 + 슬롯 구조).
- 큰 시스템(Mem0 그래프 · MemoryOS · Zep 시계열 KG · HippoRAG)은 **우리 규모에 과하다.**
⇒ 우리 규모의 최소판은 **«값 접기»**다.

**고침 ①** `merge()` — 한쪽이 다른 쪽을 통째로 품으면 접는다. **먼저 들은 것을 남긴다**
(순서가 안정적이어야 검색이 안 흔들린다).
```
[편의점] + [편의점 알바]  → [편의점]        [편의점 야간] + [편의점] → [편의점 야간]
[제과제빵] + [제빵]       → [제과제빵]      [용접] + [제빵]         → [용접, 제빵]  (무관하면 둘 다)
```
**고침 ②** `mark_slot_kind()` — 「못함」은 **품는 관계인 값에도 번지게** 한다.
  안 그러면 「편의점 알바=못함」이 접혀 사라질 때 그 «못함»이 통째로 없어진다.
```
{편의점: 해봤음} + {편의점 알바: 못함} → {편의점: 못함, 편의점 알바: 못함}
{용접: 원함}    + {제빵: 못함}        → 그대로 (무관하면 안 번진다)
```
**확인** — 접기 5/5 · 번짐 정확 · 무관 값 회귀 없음 · 골든셋 **34/34 · 87초**.

⚠ **남은 것** — `강점성향 "인내심"`(사용자가 말한 적 없다)은 여전히 막지 못한다.
  스칼라 슬롯이라 `verify_slots` 의 근거 검증 경로를 안 탄다. **미해결.**

### 18. ★★★ 「대화가 앞으로 안 나간다」를 직접 잰다 — 정체 게이지

동적 페르소나(LLM 이 연기)로 돌리자 **셋이 각각 다른 방식으로 막혔다.**

| 유형 | 막히는 이유 | 결과 |
|---|---|---|
① 정지훈 — **부정만 함** | 「못함」 무게 0 → `can_land` 영원히 False | 18턴 **카드 0개** |
⑦ 강태오 — **정보를 안 줌** | 슬롯이 안 참 | **14턴 연속** 같은 두 문장 |
④ 이하늘 — 정보를 줌 | 막히지 않음 | 정상 |

⚠ 내가 만든 장치 셋이 **전부 다른 신호**를 보고 있어서 강태오는 셋 다 피해갔다:
```

_unsure_seen  «모르겠다»를 셈    → 「아까 말했는데요」는 안 셈
drop_echo     «첫 문장» 비교     → 「죄송합니다」·「제가 아까」로 미묘히 달라 통과
```
⇒ 부정·모르겠다·문장중복은 전부 **증상**이지 정체가 아니다.
  정체는 하나다 — **N턴 동안 슬롯이 하나도 안 늘었다.** 그 한 줄로 둘 다 잡힌다.

**고침** — `_stall` 게이지(step 에서 센다) + 세 단계
```
정체 3턴  →  «먼저 보여준다» (칩)          should_nudge
정체 3턴  →  그래도 안 되면 «카드»          _stall_card
낼 때마다  →  «다른 중분류» 우선 (_stall_seen)
```

⚠⚠ **자물쇠 조건을 네 번 틀렸다. 매번 «영영 안 걸리는» 구멍이 생겼다.**
```
1차 `_nudged` 요구       → 그 표시는 «내 훅이 낼 때»만 선다. 3턴 칩은 원래 좁히기 경로였다
2차 `not can_land` 요구  → 카드가 한 번 나가 슬롯이 차면 True 가 되어 영영 안 걸림
3차 `_stall_carded` 잠금 → 한 번 내고 다시 갇힘
4차 정체 길이만 + 순번    → ✅
```
**오늘 `_ask_n`·`_asked_exp` 와 같은 병이다 — 표시를 «세우는 자리»와 «읽는 자리»가 어긋난다.**

**결과** — 세 페르소나 모두 카드가 나온다(전엔 0·1개):

- ❌ 「연구는 슬롯을 버렸다」 → **틀렸다.** DST 는 활발하다. 다만 방식이 바뀌었다:

- ❌ 「이런 조합은 없다」 → **틀렸다.** CRS+RAG+LLM 논문이 여럿이다
  (RAR arXiv:2604.04457 — 영화 30만 편, 연구 전용 · MemoCRS · Beyond Retrieval).

**✅ 정확한 위치 — 다중 세션 TOD 는 «2025년에 첫 벤치마크»가 나온 자리다**
> **Du et al. (2025)** introduced the **first multi-session task-oriented dialogue benchmark**

그리고 그 분야가 «어렵다»고 꼽는 난제 셋을 **우리가 실제로 만나 고쳤다**:
```
"resolving state changes over distant sessions"  → 「못함이 해봤음을 못 이기던」 것 (9장)
"detecting entity attribute changes"             → 「편의점」이 세 이름으로 쌓인 것 (17장)
"resisting distraction from stale evidence"      → profile_text 에 종류 전달 (11장)
```
