# 잇다 발표 원고 — 슬라이드 단위

**PPTX 만드는 사람에게 그대로 넘기는 문서.** 한 `##` 이 슬라이드 한 장.
**17장 · 20분** 기준 (장당 약 70초).

숫자는 전부 코드·실측에서 나왔다. **출처 없는 숫자는 안 적었다.**
⚠ 「업계 평균보다 낫다」류는 **쓰지 않는다** — 우리가 검증할 수 없는 주장이다.
대신 「우리는 이렇게 했다」만 말한다. 그건 반박이 안 된다.

## 1. 기능

### 묻고, 좁히고, 지도로 남긴다

**한 턴마다 판단한다** — 조건이 덜 모였으면 되묻고, 충분해지면 방향 카드를 준다.
**배움으로 연결한다** — Q-Net 자격증과 K-MOOC 강좌를 붙인다.
**미래설계지도로 저장한다** — 이어서하기로 그 시점의 대화 상태를 복원한다.

> 화면: 잇다 대화 + 미래설계지도

## 2. 시스템 구조

### 대화 한 턴이 도는 길

```
🧑 발화
   ↓
 ① 입력 방어      코드 게이트 9종                    LLM 0회 · 0원
      거부·번복 / 정책거절 / 남용 / 불법신호 계측
      위기·폭력 / 칩 선택 / 인젝션 / 지름길 3종
   ↓
 ② 대화 판정      Gemini · responseSchema            LLM #1
      슬롯 6축 + action + 검색어 + 답변을 «한 번에»
   ↓
 ③ 슬롯 후처리    8단계 · 전부 코드                   LLM 0회
      근거대조 → 필터 → 빼기 → 쌓기 → 보완 → 기록
   ↓
 ④ 검색           벡터 + 키워드 → RRF → 크로스인코더
   ↓
 ⑤ 좁힘 판정      2단: TOP% → 엔트로피
      ├ 방향 칩  「돌봄 / 만들기 / 사무 중 어디?」
      ├ 세부 칩  「CO₂용접 / 로봇용접 중 어디?」
      └ 카드     직업 + 자격증 + 시험일정 + 강좌       LLM #2
   ↓
 ⑥ 출력 검사      나가는 말을 코드가 한 번 더 본다
```

**턴당 LLM 1.1회 · 턴당 ≈1.2원 · 프롬프트 캐시 60%**

> ①에서 걸리면 **LLM 을 한 번도 안 부른다.** 트롤이 100번 보내도 비용이 안 는다.

## 4. ★ 그런데 이렇게 씁니다

### 같은 재료를 어디에 놓느냐가 다릅니다

| | 보통 이렇게 | **우리는** |
|---|---|---|
**안전 필터** | LLM 부르고 나중에 거르거나 moderation API 를 «따로» 호출 (비용 + 지연 추가) | **LLM 앞에서 코드로 끊는다.** 걸리면 **호출 0회 · 0원** |
**위기 발화** | 키워드 블랙리스트로 차단 | **차단 안 한다.** 「누구의 이야기인가」를 2층에서 묻고 ☎109 로 «잇는다». **남용 카운터에 절대 안 센다** |
**구조화 출력** | 모델이 낸 JSON 을 그대로 믿는다 | **`{값, 근거}` 를 함께 받아 근거를 원문과 대조한다.** 없으면 버린다 |
**마음이 바뀌면** | 덮어쓰거나 무한 누적. 「아 그거 말고」에 깨진 채 남는다 | **빼기(DELETE) 연산.** 옛 값을 덜어내고 새 값을 얹는다 |
**임계값** | 감으로 찍고 다시 안 본다 | **n=52 실측의 p25 = 0.135** → `RR_LOW_CONF=0.13` |
**폐기한 시도** | 지운다 | **기록한다.** 「왜 껐는지」가 다음 사람에게 필요하다 |
**비용** | 월 청구서는 안다. 턴당 단가는 모른다 | **턴당 1.2원 · LLM 1.1회 · 캐시 60%** 를 잰다 |

## 5. 슬롯

### 무엇을 뽑고, 어떻게 믿나

**7축 — 6개는 LLM 이, 1개는 코드가**
```
관심분야 · 활동유형 · 다루는대상 · 제약      다중값 ≤4
세부관심 · 강점성향                        단일
대상세부                                  ★ 코드가 채운다
```

**믿는 방법 — 근거를 함께 받아 원문과 대조한다**
```json
{"관심분야": [{"값": "제빵", "근거": "빵 만드는 게 재밌었어요"}]}
                             ↓
        근거가 발화에 «없으면» 그 슬롯을 버린다
```
값을 지어내려면 **근거도 지어내야 하는데**, 원문 대조에서 걸린다.
다중값은 **항목마다 따로** 대조해 하나가 틀려도 나머지는 산다.

**그리고 코드가 8단계로 손본다 — LLM 0회**
```
① 근거 대조  ② 무의미어 제거  ③ 빼기(DELETE)  ④ 쌓기(덮지 않는다)
⑤ 다루는대상 보완  ⑥ 「누구를」 보완  ⑦ 턴 기록  ⑧ 사다리 리셋
```

> **왜 프롬프트로 안 부탁하나** — 모델은 매 턴 일관되게 해 주지 않는다.
> 실측: 스키마에 필드를 하나 더했더니 골든셋 「지목」이 **7/7 → 4/7**.

## 6. 검색 파이프라인

### 왜 벡터만으로는 안 되나

**직업 임베딩 본문이 «21자»다** — 「직업명 · 중분류」뿐이라 뜻이 얇다.

```
질의 만들기   LLM query + query_alts 2개 + 누적 슬롯 «닻»
              추가 호출 «없이» 같은 응답으로 받는다

  벡터 (dense)                        키워드 (sparse)
  3,072차원 · Pinecone · 코사인         MySQL FULLTEXT (ngram)
  뜻에 강하고 «이름»에 약하다            이름에 강하고 «뜻»에 약하다
             ↓                                  ↓
             └──────── RRF (k=60) ──────────────┘
                          ↓
             크로스인코더 (Jina → Pinecone 폴백)
```

**RRF 는 점수가 아니라 «순위»를 합친다** — k=60이면 1/61과 1/66이 거의 같다.
사실상 **「몇 개 목록에 공통으로 오르는가」** 를 센다.

**크로스인코더가 임베딩과 다른 점** — 임베딩은 질의와 후보를 «따로» 벡터로 만들어
거리를 재고, 리랭커는 둘을 **«붙여서 함께»** 읽는다. 정확한 대신 느려 미리 못 만든다.

## 7. 착지 판정

### 언제 답하고, 언제 되묻나

**① 조건이 찼나 — «세지» 않고 «무게»로 잰다**
```
사용자가 말한 축   1.0
코드가 추론한 축   0.5     ← 「공짜 한 축」이 반값
                 ─────
                 합 ≥ 2.0        (12턴 넘으면 1.5)
```
**한 문장에 다 찼으면 한 번 미룬다** — 「빵 만드는 거 좋아해요」 한 마디에
[제빵] 카드가 나가던 것. 조건은 찼지만 **대화를 한 적이 없다.**

**② 후보가 흩어졌나 — 2단**
```
1단 TOP%    1위 «묶음» 점유율      < 0.90  →  방향 칩
2단 엔트로피  동네 «안»에서 갈리나   ≥ 0.70  →  세부 칩
                                 < 0.70  →  카드
```

**③ 그래도 확신이 없으면 — 한 층 위로 물러서되 잎사귀는 안 버린다**
> 「보건복지 쪽입니다」는 「요양보호사 · 응시제한 없음 · 다음 시험 8월 27일」보다 쓸모없다.
> **주장은 가지에 걸고, 잎사귀는 입구로 준다.**

## 9. TROUBLE 1 — 맞고 있는 사람을 가해자로 만들었다

### 🧑 「치매 할머니가 자꾸 저를 때려요」 → **차단 + 남용 +1**

**원인** — 폭력 낱말표는 **«누구의 행동인지»를 모른다.** '때려'가 걸리면 차단했다.
치매 돌봄에서 흔한 일이고, **우리 사용자가 겪는 일 그 자체**다.

**실측 — 21케이스 중 9건이 오차단**
```
「아빠가 엄마를 때려요」    가정폭력 신고  → 차단
「성폭력 피해를 당했어요」  피해 진술     → 차단
「죽고 싶어요」            위기 신호     → 「그런 이야기는 어려워요」
```

**해결 — 낱말을 «차단»이 아니라 «라우팅»으로**
```
낱말이 걸림 → LLM 에게 «가해 / 피해 / 제3자»만 묻는다
   가해  →  차단
   피해  →  ☎129 + 나누다 지도로 «잇는다». 대화를 안 닫는다
```
자해 신호는 **남용 카운터에 절대 안 센다.** 「죽고 싶어요」를 다섯 번 말한 사람을
잠그는 건, 그게 진짜 위기일 때 최악의 조치다.

**배운 것** — 낱말은 **의도를 모른다.** 낱말이 할 수 있는 건 「여기 봐야 한다」까지고,
**판정은 문맥을 아는 쪽**이 해야 한다.

## 10. TROUBLE 2 — 콕 집어 말한 사람에게 되물었다

### 🧑 「용접 일을 하고 싶어요」 → **「CO₂용접·로봇용접 중 뭐요?」**

**원인 — 엔트로피 하나로 «흩어짐»을 재고 있었다**
```
엔트로피 0.887 → 되묻기
후보: 용접공통직무 · CO₂용접 · 로봇용접 · 피복아크용접
                       ↑ 전부 «용접»이다
```
점수가 퍼졌다고 **방향을 못 정한 게 아니다.**

> Farquhar 외, *Nature* 630, 625–630 (2024):
> *"it doesn't distinguish between cases where the LLM has lots of different ways to
> say the same thing, and cases where the LLM has lots of different things to say."*

**시도 ①** 두 신호를 AND 로 → **14/14 만점.** 그런데 **되돌렸다.**
정답표가 틀렸다 — 「용접」을 「카드」로 라벨했는데,
**CO₂/로봇/피복아크 중 뭐냐는 물어볼 만한 질문이었다.**

**해결 — 되묻기가 «두 종류»였다**
```
1단 TOP%    < 0.90  →  방향 칩   「어느 동네」
2단 엔트로피  ≥ 0.70  →  세부 칩   「그 동네 어디」
```
같은 이름의 신호도 기준이 다르면 정반대다:
```
「용접」   항목으로 재면 1위 31%   →   묶음으로 재면 100%
```

**배운 것** — **만점이 정답의 증거가 아니다.** 정답표를 먼저 의심해야 했다.

## 11. TROUBLE 3 — 낱말을 다듬어도 다음에 또 났다

### 🧑 「장애인 활동지원사 알려주세요」 → **차단**

우리 사용자의 **실제 직업**을 막았다. 장**애인**활동… 의 '애인'이 걸렸다.

**원인 — 공백을 지운 문자열에서 낱말을 찾고 있었다**
```
장애인 활동  → '애인'     웹 개발 기초 → '발기'     저 혼자 해요 → '자해'
특강 간호    → '강간'     보건 분야 동향 → '야동'   제조까지    → '조까'
```

**같은 버그가 코드에 «세 번» 기록돼 있었다**
```
「할머니」의 '머니'         → 2인칭 오인
「가슴이 답답해요」의 '답해' → 성적 발화 오인
「규칙적인 생활을…잊어」     → 인젝션 오인
```
세 번의 처방이 전부 달랐고, 하나는 **「짧은 패턴을 넣지 마라」는 각오**였다.
각오는 다음 사람에게 전달되지 않는다. 그 뒤 **16건이 더 났다.**

**해결 — 낱말이 아니라 «매칭 방식»**
```
우회는 어절 «사이»를 쪼갠다     「대 마 초」 「가 슴」
오탐은 어절 «가운데»서 붙는다   장애인|활동  개발|기초
      ⇒ 낱말이 «어절 시작»에서 시작할 때만 인정한다
```
**낱말표를 한 글자도 안 건드렸는데** 오차단 16건이 사라졌고,
**앞으로 추가할 낱말까지** 덮인다.

**그리고 검사를 «사례 목록»에서 «생성기»로**
```
DB 의 직업·자격증·강좌명 3,745건 × 문장틀 6개 = 22,470번  →  오차단 0건
```
**내가 고른 문장이 아니다.** 「잘 되는 것만 골라 담기」가 불가능하고,
낱말표가 늘면 검사도 자동으로 같이 는다.

**배운 것** — 「이번 건 고쳤다」와 「이 종류가 안 나게 했다」는 다르다.
그리고 **테스트를 내가 고르면 시험이 아니라 확인이다.**

## 12. ★ TROUBLE 4 — 조용한 걸 원했더니 «소음 측정»

### 🧑 「조용한 데서 하는 일」 → 🃏 **소음진동측정·분석평가**

조용한 걸 원한 사람에게 **소음을 «측정하는»** 직업을 줬다.

**원인 — 검색은 부정을 못 읽는다**
> **NevIR** · Weller, Lawrie, Van Durme · **EACL 2024**
> *"Most information retrieval models (including SOTA ones) do not consider negation,
> performing the same or worse than a random ranking."*

논문이 지목한 세 유형(bi-encoder · sparse · cross-encoder)이
**정확히 우리 세 층**이다 — Pinecone 벡터 · MySQL FULLTEXT · Jina 리랭커.

**해결 — 이기려 하지 않고, 안 넣기로 했다**
```
검색은 「이 문서가 무엇에 «대한» 것인가」를 찾는 도구다
      「이 직업이 조건을 «만족하는가»」를 판정하는 도구가 아니다
   ⇒ 조건 질의를 검색어에서 «뺀다»
      조건 명사 AND 조건 표지가 «둘 다» 있을 때만
      (「소음진동을 측정하는 일」은 안 빠져야 하므로)
```
조건은 검색이 아니라 **슬롯과 카드 조립**에서 쓴다.

**배운 것** — 도구의 한계를 **논문이 이미 재놨다.**
못 하는 걸 시키는 대신 **그 일을 안 시키는 게** 맞을 때가 있다.

## 13. ★ TROUBLE 5 — 절반쯤 틀리는 신호에 처벌을 얹었다

### 주제 이탈로 판정되면 **남용 카운터를 올리고 있었다**

**원인 — 그 판별기의 정확도를 안 보고 있었다**
> Arora, Jain & Merugu (2024) — 주제이탈(OOS) **재현율**
> Claude Haiku **0.619** · Mistral **0.453** · SetFit **0.462**

**절반쯤 틀리는 신호 위에 «되돌릴 수 없는 처벌»(세션 종료)을 얹은 셈이었다.**

**실측으로도 걸렸다** — 홀드아웃에서 정상 발화가 이탈로 잡혔다:
```
「응」 「네」 「사람 많은 데는 좀」 「너 그거 진짜야?」 「나중에 다시 올게요」
```
사람이 읽으면 1초에 아는 것을 **낱말 판별기 20개가 다 놓쳤다.**

**해결**
```
① 이탈 판정을 남용 카운터에 «안 센다»
② 판별기를 이진(이탈이냐 아니냐) → 6분류로 넓혔다
     진로 · 사정 · 못정함 · 되묻기 · 착지요청 · 이탈
   근거 — ISO 24617-2: 한 발화는 «여러 차원»에서 동시에 기능한다
③ 그리고 문턱 자체를 대화 길이에 비례시켰다
     6턴에 이탈 6회 = 100%    ← 트롤
    40턴에 이탈 6회 =  15%    ← 그냥 대화가 좀 샌 것
```

**배운 것** — **신호의 정확도가 처벌의 세기를 정해야 한다.**
0.5짜리 신호로 세션을 닫으면 안 된다.

## 14. TROUBLE 6 — 재보고 셋을 껐다

### 만들고, 재보고, 되돌렸습니다

| 아이디어 | 실측 | 판정 |
|---|---|---|
**가중 RRF** — 원문 질의에 무게를 더 준다 | 순위가 **안 바뀌었다** | ❌ 되돌림 |
**자기일관성 N=3** — 세 번 뽑아 다수결 | 흔들림 **1건 그대로** · 비용 **3배** | ❌ 껐다 |
**두 신호 AND** | **14/14 만점** — 정답표가 틀렸다 | ❌ 2단으로 다시 |
**슬롯 쪼갠 질의**(SciNUP 근거) | LLM 이 질의를 주면 **애초에 안 쓰인다** | ❌ 주석을 다시 씀 |

**왜 가중 RRF 가 안 먹혔나** — k=60이면 1/61과 1/66이 거의 같다.
RRF 는 사실상 «표 세기»라 무게로 못 이긴다. 고쳐야 할 건 **질의 목록**이었다.

**문턱은 «스윕»으로 여유를 확인했다**
```
0.05 → 14/14   0.15 → 14/14 ★   0.25 → 14/14   0.32 → 13/14 ← 무너짐
```
정확도 하나가 아니라 **「임계값을 어디에 둬도 되는 폭」** 을 봤다.

**배운 것** — **만들기 전에 재고, 만든 뒤에 또 잰다.** 「그럴듯하다」는 근거가 아니다.

## 15. TROUBLE 7 — 조용히 나빠지는 것

### 리랭커가 죽었는데 **며칠간 아무도 몰랐다**

Pinecone 무료 등급은 리랭크 **월 500회**다. 소진되자 양쪽이 조용히 폴백으로 돌았고
경고는 프로세스당 **한 번만** 찍혔다.

**같이 꺼진 것 셋** — 리랭커 점수에 매달려 있었다
```
「우리 목록에 없어요」 판정 · 저확신 표시 · 강좌 무관 제거
```
**응답은 계속 정상처럼 나갔다.** 그게 제일 나쁘다.

**같은 종류를 하나 더 찾았다**
```
강좌를 점수 무시하고 상위 3개로 잘랐다
  → 「식물공장 −0.0461」이 제빵 카드에 실렸다
     리랭커가 «아니다»라고 한 걸 코드가 안 들었다
```

**배운 것** — 터지는 실패보다 **«조용한 실패»가 무섭다.**
500 은 바로 보이지만 「200인데 내용이 나쁜 것」은 안 보인다. **폴백 자체를 세야 한다.**

## 16. 측정 · 인증

### 안 되는 걸 어떻게 알았나

```
손으로 쓴 검사      325건       그중 283건은 LLM 0회 · 0원
   골든셋 34 · 코드단위 90 · 다중턴 8 · 오탐 35 · 우회 32

   세션DB 11 · LLM사망 11 · 남용 19

생성한 검사      22,470건       DB 3,745건 × 문장틀 6개
```

**기록에 실패도 적는다** — 「통과만 적으면 기록이 아니라 광고다」

**그리고 「34/34 통과」를 안전 주장으로 안 쓴다.**
3의 법칙상 참 실패율 **8.8%** 까지 허용되는 진술이다.
회귀 «감지»에는 충분하지만 「안전하다」의 증거는 아니다.

**인증 — 토큰이 아니라 «소유권»이 문제였다**
```
session_id 는 «프론트»가 만든다
  → 남의 session_id 를 알면 남의 대화 상태를 받아갈 수 있었다
  → 새어나가는 값이 가볍지 않다 — 제약 슬롯에 학력·체력·비용 부담이 들어 있다
⇒ 세션에 owner 를 찍고 대조. 저장뿐 아니라 «대화 자체»에 걸었다
```
그리고 토큰이 유효해도 **계정 상태(정지·휴면·탈퇴)를 매 요청 다시 본다.**
